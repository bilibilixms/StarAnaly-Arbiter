## 验证顺序

所有命令在仓库根目录执行。两个验证脚本只依赖 Python 3 标准库。数据库和模型凭据继续从测试机器的环境变量读取；脚本不会打印密钥，也不会读取 `.env` 文件。基线脚本会**创建一条任务并发送一条模型消息**，请在测试数据库上运行。

1. 启动 MySQL、后端和前端，按 [README](../README.md#本地运行) 配置环境。后端成功启动表示 Flyway 已执行迁移，并通过 Hibernate 表结构校验。
2. 在已配置模型环境变量的终端运行 `python3 scripts/verify_baseline.py`。如后端不在本机，使用 `--api-base-url http://主机:端口`。脚本核对任务创建、详情、分页列表、模型回复、消息持久化和最终状态。
3. 在同一终端运行 `python3 scripts/probe_model_tools.py`。此脚本按 [DeepSeek 的工具调用格式](https://api-docs.deepseek.com/guides/tool_calls/) 访问 `MODEL_BASE_URL/chat/completions`，要求模型调用一个仅用于探测的加法函数，再将结果 `5` 回传。DeepSeek 默认开启思考模式，而指定工具调用在该模式下不可用，因此脚本会为 DeepSeek 请求关闭思考模式。脚本不执行函数，也不改动数据库；读取 `MODEL_API_KEY` 或 `DEEPSEEK_API_KEY`，默认模型为 `deepseek-flash`，默认地址为 `https://api.deepseek.com`。
4. 在另一台机器按需运行 `mvn test` 和 `cd frontend && npm run build`；浏览器确认任务创建、详情、发送消息和刷新对话流程。

若失败，请反馈**失败的步骤、HTTP 状态、脱敏后的错误信息**，以及实际模型名称；不要发送 API 密钥或数据库密码。工具调用探测失败时，先区分接口不支持、账号权限/额度问题、网络问题和模型返回格式问题，再决定第 3 周的适配方案。

## 现有接口契约

| 操作 | 方法与路径 | 关键请求/响应 |
| --- | --- | --- |
| 创建任务 | `POST /api/tasks` | JSON：`title`、可选 `description`；成功 `201`，返回 `id` 与 `PENDING` |
| 列表与详情 | `GET /api/tasks?page=0&size=20`、`GET /api/tasks/{id}` | 列表为分页对象；详情含 `status`、`lastError` |
| 发送消息 | `POST /api/tasks/{id}/messages` | JSON：`content`；同步等待模型回复，成功返回 `ASSISTANT` 消息 |
| 消息记录 | `GET /api/tasks/{id}/messages` | 返回按创建顺序排列的 `USER`、`ASSISTANT` 消息 |

当前同一任务并发发送返回 `409`，不存在的任务返回 `404`，非法输入返回 `400`，模型未配置返回 `503`，模型调用失败返回 `502`。模型回复成功后任务为 `SUCCEEDED`，失败后为 `FAILED`，原因保存在 `lastError`。第 2 周新增执行 API 时保留这些现有接口的可用性。

## 第 2～3 周实施设计

这部分是编码前的接口与数据结构约定；第 1 周的模型探测结果可能影响工具适配细节。

1. **一次消息对应一次执行。** 新增任务执行记录及有序步骤记录。执行记录至少包含任务 ID、输入摘要、状态、开始/结束时间与可公开的错误原因；步骤包含序号、类型、状态、工具名称、耗时和结果摘要。任务状态反映最近一次执行状态。步骤按数据库序号读取，不依赖客户端时间排序。
2. **新增可查询的执行入口。** 计划使用 `POST /api/tasks/{id}/runs` 创建执行并返回执行 ID，`GET /api/tasks/{id}/runs/{runId}` 与 `/steps` 查询进展。耗时任务由后端执行，页面轮询。现有 `POST /messages` 保留基础对话能力；新入口复用同一执行状态机，不建立第二套消息历史。
3. **并发与恢复。** 每个任务同一时间最多一条 `RUNNING` 执行；并发请求返回 `409`。执行失败或进程中断时写入失败状态；重试通过新的执行记录进行，不覆盖旧步骤。数据库事务只包围状态/记录写入，远程模型调用不占用事务。
4. **模型适配边界。** 扩展当前文本网关为“文本回复或工具请求”的结果类型。模型只提出工具名与 JSON 参数；应用用白名单选择工具，校验参数，再执行并回传结果。单次执行限制模型轮次、工具次数、响应大小与总时长。工具调用、工具结果和最终回答都留有可查询步骤。
5. **数据与日志边界。** 执行步骤保留必要的摘要和引用 ID；API 密钥、原始模型请求头、完整上传文件不写入步骤或普通日志。分析结果和知识引用按明确结构保存，便于前端展示及后续核对。

第 2 周开始前需要确认：测试机的基线结果、实际模型是否支持工具调用、演示文件格式及初版大小上限。若模型不支持标准 `tool_calls`，先记录实际响应格式，再确定适配或改用显式触发的受控分析流程。
