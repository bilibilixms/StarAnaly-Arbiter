# 星析 Agent 开发规划说明书（讨论稿）

> 版本：0.1 · 编写日期：2026-10-20 · 计划周期：启动后 7～9 周，按 8 周排期

## 1. 目标与计划边界

本轮目标是交付一个可在单用户测试环境中演示的智能任务工作台：用户创建任务，上传资料或 CSV，提出问题；系统调用受控工具完成检索或计算，保存执行步骤，在页面展示回答、数据结果和来源。计划从当前仓库继续开发，不把已完成的任务 API 和基础对话重新计算为未来交付物。

以下是排期假设，启动第 1 周时需要核实：

- 以一条主要开发线推进；代码由开发方编写，用户在另一台机器提供环境并运行集成测试、验收。
- 首个交付场景为单用户或受控内网试用。公开部署、多用户隔离和账号体系不计入本轮范围。
- 模型服务采用 DeepSeek，由环境变量配置；第 1 周确认实际接入地址、模型名称、接口兼容性、调用额度及测试数据。
- 知识资料先支持 UTF-8 的 TXT、Markdown；结构化分析先支持 CSV。PDF、Excel、网页抓取和外部系统写入列为后续候选。
- MySQL 继续保存业务数据；Redis 暂不作为必选依赖。检索索引方案需通过小规模实测确定，避免在计划阶段锁定新服务。

## 2. 当前基线

截至提交 `3b1681a`，仓库已有 Spring Boot + MySQL + Flyway 后端、Vue 3 + TypeScript 前端、任务创建与查询、按任务保存的模型对话、任务状态和失败原因。模型调用使用兼容 Chat Completions 的文本接口，尚无工具调用、知识库、CSV 分析、执行步骤记录和成果展示。现有接口测试为模拟测试；实际环境中的数据库迁移、模型连接和前端联调还需由用户验证。

## 3. 本轮交付范围

| 模块 | 最小可交付能力 | 验收证据 |
| --- | --- | --- |
| 任务执行 | 任务有独立执行记录、步骤、结果和失败原因；重复请求受到约束 | 页面能还原一次成功或失败的执行过程 |
| 模型与工具 | 识别工具请求，校验参数，按白名单执行，限制调用轮次和超时 | 同一任务能完成一次“模型请求 → 工具 → 模型回答”闭环 |
| 数据分析 | 上传 CSV，预览字段，进行筛选、分组汇总和基础统计 | 固定样例的汇总数值与人工计算一致 |
| 知识检索 | 上传 TXT/Markdown，建立索引，检索相关片段并标注来源 | 回答可定位到原文档和片段；无证据时明确说明 |
| 前端工作台 | 展示文件、执行步骤、分析结果、引用和错误恢复入口 | 用户可在浏览器完成完整演示，无需手工调用 API |
| 交付质量 | 迁移、关键接口、工具边界和前端构建可验证；操作文档齐全 | 用户测试机器上的检查结果和演示记录 |

本轮不包含自主访问互联网、任意代码执行、任意 SQL、外部账号操作、自动发送消息或不可逆写入。若后续加入有副作用的工具，需单独定义权限和用户确认流程。工具参数校验、权限边界和执行记录是设计的一部分；这是基于 [Spring AI 对工具执行责任的说明](https://docs.spring.io/spring-ai/reference/1.0/api/tools.html) 以及 [OWASP 对 Agent 过度授权风险的建议](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/?lang=us) 制定的项目约束。

## 4. 周计划与里程碑

每周末以可运行的代码、迁移文件、接口/页面和验收记录作为完成依据；若前一周的关键验收未通过，优先修复后再进入依赖它的功能。

| 周次 | 主要工作 | 周末交付与验收 |
| --- | --- | --- |
| 第 1 周：基线验证与设计 | 在用户测试机核对现有数据库迁移、模型连接和前端流程；固定演示数据与接口契约；验证目标模型是否支持工具调用；明确文件大小与格式上限 | 现有创建任务、对话和前端流程跑通；形成工具/执行记录的数据结构设计和已知问题清单 |
| 第 2 周：执行记录 | 增加执行记录、步骤事件、结果及错误数据；将当前一次性同步对话扩展为可查询的执行过程，明确超时和重试语义 | API 能查询步骤与最终状态；服务中断、模型失败和重复发送都有可解释的结果 |
| 第 3 周：工具闭环 | 增加模型工具调用适配、工具注册与参数校验、轮次/时间限制；先接入只读演示工具 | 通过端到端样例证明工具调用、结果回传和步骤记录；非法工具名及参数被拒绝 |
| 第 4 周：CSV 数据分析 | 文件上传与校验、CSV 解析、字段预览、筛选及分组汇总；分析工具接入任务执行链 | 用固定 CSV 样例完成“按月汇总”任务，数值与预期结果一致，错误文件有明确提示 |
| 第 5 周：知识检索 | TXT/Markdown 解析、分段、索引、检索、来源标识及资料删除；根据第 1 周实测确定检索实现 | 资料问答能返回来源；检索不到证据时不编造引用；删除资料后不再命中 |
| 第 6 周：前端完整流程 | 文件上传、执行步骤、CSV 结果、知识引用和异常状态页面；补充必要的空状态与重试操作 | 浏览器中可完成两个演示场景：CSV 分析和资料问答 |
| 第 7 周：集成与质量 | 覆盖数据库迁移、工具边界、文件解析、检索及前端构建的关键检查；修复用户测试机发现的问题；核对日志不含密钥或原始敏感内容 | 关键检查通过；失败与恢复场景可复现；形成待修问题列表 |
| 第 8 周：验收与交付 | 回归两个完整场景，整理部署/配置/数据备份与限制说明，处理阻断验收的问题 | 用户测试机完成演示与验收；README、接口说明、已知限制和版本提交齐备 |

### 7 周与 9 周的调整方式

- **7 周完成**：仅在第 1～3 周的环境与工具调用验证顺利、用户反馈及时的前提下，把第 6 周的前端集成随第 4～5 周并行推进，并把第 8 周的文档和验收并入第 7 周。关键检查与验收标准不缩减。
- **8 周基准**：按上表推进，每周留出修复和联调时间。
- **9 周完成**：当模型兼容性、检索选型或真实环境迁移出现阻断时，增加第 9 周用于适配、回归及验收；不临时加入 PDF、Excel 等新范围。

## 5. 关键依赖与验收口径

1. **第 1 周先验证真实环境。** 用户提供测试结果、接口错误及脱敏日志；开发方根据反馈修复。模型密钥、数据库密码只在测试机器的环境变量中配置，不写入仓库。
2. **执行记录先于复杂工具。** 工具调用必须能记录输入摘要、执行状态、耗时和结果摘要；完整文件内容与密钥不进入普通日志。
3. **分析结果可复核。** CSV 汇总使用确定性代码计算，模型负责选择工具和解释结果；验收以固定样例的准确数值为准。
4. **知识回答可追溯。** 检索链至少保留文档名和片段定位，页面展示引用；检索策略可按实测选用关键词、向量或组合方式。[Spring AI 的 RAG 文档](https://docs.spring.io/spring-ai/reference/api/retrieval-augmented-generation.html) 可作为实现方案参考，是否引入该依赖由第 1～5 周的兼容性和复杂度评估决定。
5. **每周提交可回退。** 数据库变更使用新的 Flyway 迁移；接口、前端与文档同步更新。用户在另一台机器运行 `mvn test`、前端 `npm run build`，并执行当周演示用例。

最终验收至少覆盖三类用例：用固定 CSV 得到准确的按月汇总并看到执行步骤；用指定资料回答问题并能查看原文出处，删除资料后无法再引用；对错误文件、不可用模型和非法工具请求给出可恢复的失败状态。上述用例在用户测试机完成，且后端测试、前端构建与旧数据库升级检查通过，才视为本轮交付完成。

## 6. 风险、决策点与变更规则

| 风险或待定事项 | 计划内处理 |
| --- | --- |
| 目标模型只兼容文本对话，不支持标准工具调用 | 第 1 周完成能力探测；第 3 周前确定适配方式。若无法支持自动工具闭环，先交付显式触发的受控分析流程，并重新评估 Agent 场景验收 |
| 检索方案需要新模型或新基础设施 | 先用少量真实样本比较召回质量与部署成本；选型记录在文档中，新服务需同步提供部署步骤 |
| 用户测试反馈晚于开发节奏 | 每周固定交付一个可验证增量；未验证的依赖项不算完成，后续范围顺延 |
| CSV 格式和资料规模超出初版上限 | 第 1 周确定样例、编码、大小和行数上限；超出范围进入后续迭代 |
| 新增多用户、公开部署或外部写入工具 | 作为范围变更单独估时，并补充身份验证、授权和审计要求 |

每周评审只做三件事：核对交付物与验收结果、记录阻断问题、调整下周优先级。改变里程碑或增减范围时，同步更新本说明书的版本、预计完成周次和验收标准。
