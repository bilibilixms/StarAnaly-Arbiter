# 第 3 周：只读工具调用闭环

> 状态：代码待用户测试机验证 · 对应 [开发规划](development-plan.md) 第 3 周

## 实现范围

任务对话现在可由 DeepSeek 请求 `sum_two_numbers`。应用仅接受这个白名单工具，校验 `a`、`b` 为绝对值不超过 1,000,000 的整数，拒绝额外字段，并在进程内计算结果。模型只能提出工具调用；应用负责执行并把结果作为 `tool` 消息回传。工具没有网络、文件、数据库写入或任意代码执行能力。

一次执行最多 3 次模型请求、2 次工具调用，总时长最多 120 秒；单次模型请求最多等待 90 秒。模型响应、工具参数与最终回答均有限长。DeepSeek 请求会关闭思考模式以兼容已验证的工具调用格式。模型返回非法工具名、非法参数、重复调用编号或超出限制时，执行变为 `FAILED`，原因可在执行详情与失败步骤查看。旧的纯文本对话仍走同一入口。

步骤按顺序记录 `MODEL_CALL`、`TOOL_CALL`、`TOOL_RESULT`、`MODEL_CALL`、`FINAL_ANSWER`。步骤只保存必要的整数参数摘要、工具名称与结果摘要，不保存模型密钥或完整请求。第 2 周的 V3 表结构已经包含这些字段，因此本周没有新的数据库迁移。

## 测试机器上的验收

后端更新后，在仓库根目录运行：

```bash
mvn test
python3 scripts/verify_tool_loop.py
```

第二个脚本会创建测试任务，并请求模型调用整数加法工具计算 `2+3`。它会检查执行状态、步骤顺序、结果 `5` 和最终回复。模型可能自主选择直接回答；如果脚本提示缺少工具步骤，请提供脱敏后的步骤列表与实际模型名称，不要提供密钥。旧接口回归可继续运行 `python3 scripts/verify_baseline.py` 和 `python3 scripts/verify_runs.py`。

第 2 周 [验证报告](../fox.md) 中尚未实测服务重启恢复。本周验收可在测试数据库中构造一条 `RUNNING` 执行，重启应用后检查执行、未完成步骤和任务均转为 `FAILED`；避免在生产数据上手工修改状态。
